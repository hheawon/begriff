# 베그리프 (Begriff)

칸트 『순수이성비판』 개념어 대조·해설 웹앱. 팀 "세 비판".

## 내 컴퓨터에서 실행하기 (PowerShell)

```powershell
npm install        # 처음 한 번만
npm run dev        # 화면에 나오는 http://localhost:5173 주소를 브라우저로 연다
```

> "이 시스템에서 스크립트를 실행할 수 없으므로…" 오류가 나면 `npm` 대신 `npm.cmd`를 쓰세요.
> 예: `npm.cmd run dev`

## 용어 DB 고치는 방법

앱은 `data/terms.json`을 읽습니다. 이 파일은 **직접 고치지 않습니다.**
팀은 스프레드시트로 작업하고, CSV로 저장한 다음, 명령어 한 줄로 JSON을 다시 만듭니다.

```
스프레드시트 → (CSV로 저장) → data/terms.csv → (npm run build:terms) → data/terms.json → 앱
```

### 1. 스프레드시트 양식

`data/terms-template.csv`가 빈 양식입니다. **첫 줄(머리글)은 바꾸지 마세요.**
한 줄에 번역어 하나를 적습니다.

| 열 | 무엇을 적나 | 예 |
|---|---|---|
| 원어 | 칸트의 독일어(라틴어) 용어 | transzendental |
| 번역어 | 그 역본이 쓴 한국어 | 선험적 |
| 역본 | 역자·출판사 (같은 책은 매번 똑같이) | 역자 이름 역, 출판사 |
| 원문위치 | 원전 A/B판 쪽수 | B25 |
| 해설 | 이 원어의 뜻을 짧게 | 경험의 가능 조건을 다루는 인식의 성격… |
| 판단단서 | AI가 문맥에서 이 원어로 판정할 때 볼 단서 | "인식 방식", "가능 조건"과 함께 쓰임 |

- 같은 원어는 여러 줄에 걸쳐 적습니다. 앱에서는 원어별로 한 카드에 묶입니다.
- 원문위치·해설·판단단서는 **원어마다 첫 줄에만 적어도 됩니다.** 다른 줄에 다른 내용을 적으면 모두 모아서 보여 줍니다.
- 지금 들어 있는 샘플은 역본이 모두 `(확인 필요)`입니다. 책을 확인해서 채워 주세요.
  원문위치(B2-3, B25, A296/B352)와 해설도 팀이 한 번 더 확인해 주세요.
- 저작권: 번역서 문장을 길게 옮기지 마세요. 번역어·역자·짧은 인용만 적습니다.

### 2. CSV 저장 방법

한글이 깨지지 않게 꼭 **UTF-8** 형식으로 저장하세요.

- **구글 시트:** 파일 → 다운로드 → 쉼표로 구분된 값(.csv)
- **엑셀:** 파일 → 다른 이름으로 저장 → 파일 형식에서 **"CSV UTF-8(쉼표로 분리)"** 선택
  - ⚠️ 그냥 "CSV(쉼표로 분리)"를 고르면 한글이 깨집니다. 꼭 **UTF-8**이 붙은 것을 고르세요.

저장한 파일의 이름을 `terms.csv`로 바꿔서 `data` 폴더의 `terms.csv`를 덮어쓰세요.

### 3. 앱에 반영하기 (PowerShell)

프로젝트 폴더(`begriff`)에서 실행합니다.

```powershell
npm run build:terms
```

`완료: 원어 3개, 번역어 9개 → data\terms.json` 처럼 나오면 성공입니다.
`npm run dev`가 켜져 있다면 화면이 저절로 새로 고쳐집니다.

### 4. 오류가 나면

| 메시지 | 이유와 해결 |
|---|---|
| 한글이 깨진 CSV입니다 | UTF-8이 아닌 형식으로 저장했습니다. 위 "CSV 저장 방법"대로 다시 저장하세요. |
| 첫 줄(머리글)이 양식과 다릅니다 | 머리글 글자가 바뀌었습니다. `data/terms-template.csv`의 첫 줄을 그대로 복사하세요. |
| N번째 줄: "원어" 칸이 비어 있습니다 | 그 줄의 원어(또는 번역어)를 채우거나 줄을 지우세요. |
| N번째 줄: 칸이 6개여야 하는데… | 칸 수가 맞지 않습니다. 스프레드시트에서 다시 저장하면 대부분 해결됩니다. |
| CSV 파일을 찾을 수 없습니다 | `data/terms.csv` 파일 이름과 위치를 확인하세요. |

오류가 나면 `data/terms.json`은 바뀌지 않습니다. 앱은 이전 내용 그대로 돌아갑니다.

## 테스트 문장 (`data/test-sentences.json`)

AI 판정 정확도를 재고(7단계) 시연할 때 씁니다. **팀원은 JSON을 직접 고치지 말고 아래 스프레드시트 방식으로 작업하세요.**

### 스프레드시트로 작성하기

1. 구글 스프레드시트를 새로 만들고, `data/test-sentences-template.csv`를 열어 첫 줄(머리글)을 그대로 복사해 붙입니다.
   열 순서: `문장 | 개념어 | 정답원어 | 출처`
2. 한 줄에 문장 하나씩, 10~20줄을 채웁니다.

| 열 | 적을 내용 | 예시 |
|---|---|---|
| 문장 | 번역서·논문 속 『순수이성비판』 문장 그대로 (한두 문장만) | 수학적 판단은 모두 선험적 종합판단이다. |
| 개념어 | 그 문장에서 판정할 한국어 단어 하나 | 선험적 |
| 정답원어 | 독일어 원전에서 확인한 원어 | a priori |
| 출처 | 역자, 출판사, 쪽수 / 원전 A·B판 쪽수 | ○○ 역, ○○출판사, 123쪽 / B14 |

3. 다 채우면 **파일 → 다운로드 → 쉼표로 구분된 값(.csv)**으로 저장해 `data/test-sentences.csv`라는 이름으로 프로젝트 폴더의 `data` 안에 넣습니다. 그다음 Claude Code에 "테스트 문장 CSV 반영해 줘"라고 하면 앱이 읽는 JSON으로 바뀝니다.

**지킬 것**
- 정답원어는 반드시 독일어 원전에서 확인합니다. 이 칸이 채점 기준입니다.
- 정답원어는 용어 DB의 원어 이름과 똑같이 씁니다: `a priori`, `transzendental`, `transzendent` (띄어쓰기·소문자 그대로)
- 개념어는 용어 DB(`data/terms.csv`)의 번역어 칸에 있는 단어만 씁니다. DB에 없는 단어는 앱이 찾지 못합니다.
- 한 문장에 같은 단어가 두 번 나오면, 같은 문장을 두 줄로 적지 말고 판정할 단어가 하나인 문장을 고릅니다.
- 원어를 골고루 섞습니다. 예(15개): '선험적'=transzendental 5, '선험적'=a priori 5, '초월적'=transzendental/transzendent 3~4, 짧아서 헷갈리는 문장 1~2
- **맨 위 3줄은 발표 시연용 문장**으로 둡니다. 앱의 "예시 문장" 버튼 3개가 이 3줄을 보여줍니다.
- 저작권: 짧은 인용만. 문단 통째로 넣지 않습니다.
- 용어 DB의 판단단서를 테스트 문장에 맞춰 고치지 않습니다. (시험 문제를 보고 답을 외우는 셈이라 정답률을 믿을 수 없게 됩니다)

### 앱이 읽는 형식 (참고)

문장 하나가 `{ }` 하나입니다.

```json
[
  {
    "문장": "번역서 속 문장 (짧게)",
    "개념어": "문장 속 한국어 개념어, 예: 선험적",
    "정답원어": "transzendental",
    "출처": "역자, 출판사, 쪽수"
  }
]
```

지금 들어 있는 3개는 임시 예시입니다(B25 취지를 풀어 쓴 문장 1개 + 디자인 가이드 예시 2개). 팀 문장이 들어오면 바뀝니다.

## AI 문장 분석 API (`/api/analyze`)

번역 문장을 보내면 용어 DB만 근거로 개념어를 찾고 원어를 판정해 JSON으로 돌려줍니다.

| 파일 | 역할 |
|---|---|
| `api/analyze.js` | 주소 `/api/analyze`. 요청을 받아 입력을 검사하고 한국어 오류 메시지를 돌려줌 |
| `server/analyze.js` | AI에게 줄 지시문·답 형식, AI 답 검사(위치 계산, 판정 보류, DB 근거 붙이기) |
| `server/llm.js` | **AI(Gemini)를 부르는 유일한 파일.** 모델을 바꿀 때 이 파일만 고침 |

### API 키 넣기 (키는 채팅·카톡·GitHub에 절대 올리지 마세요)

1. **내 컴퓨터:** 프로젝트 폴더(`begriff`)에 `.env`라는 이름의 파일을 만들고 아래 한 줄을 적어 저장합니다.
   ```
   GEMINI_API_KEY=발급받은키
   ```
   `.env`는 `.gitignore`에 들어 있어서 GitHub에 올라가지 않습니다.
2. **배포 사이트(Vercel):** Vercel 대시보드 → 프로젝트 → Settings → Environment Variables →
   Key에 `GEMINI_API_KEY`, Value에 키 → Save → Deployments 탭에서 최신 배포 오른쪽 `⋯` → Redeploy.

### 시험해 보기 (PowerShell)

```powershell
# 방법 1: 터미널에서 바로
npm run try:analyze -- "모든 인식을 선험적이라고 부른다"

# 방법 2: 개발 서버를 켠 상태(npm run dev)에서 다른 PowerShell 창으로
Invoke-RestMethod -Method Post -Uri http://localhost:5173/api/analyze -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes('{"문장":"모든 인식을 선험적이라고 부른다"}')) | ConvertTo-Json -Depth 6
```

### 결과 형식

```json
{
  "문장": "...",
  "개념어목록": [{
    "단어": "선험적",
    "위치": { "시작": 7, "끝": 10 },
    "판정원어": "transzendental",
    "확신도": "높음",
    "판정보류": false,
    "후보원어": ["a priori", "transzendental"],
    "판정이유": "...",
    "해설": "...",
    "근거": [{ "원어": "transzendental", "역본": "...", "원문위치": "B25" }]
  }]
}
```

- `위치`: 문장의 몇 번째 글자부터 몇 번째 글자 앞까지인지 (0부터 셈). 화면 하이라이트에 씀.
- 확신도가 "낮음"이거나 AI가 후보가 아닌 원어를 고르면 `판정보류: true`, `판정원어: null`이 되고 `후보원어`를 보여 줍니다.
- `근거`(역본·원문위치)는 AI가 쓰지 않고 **용어 DB에서 그대로** 붙입니다. 그래서 출처를 지어낼 수 없습니다.
- 문장은 500자까지. 오류일 때는 `{ "오류": "한국어 메시지" }`를 돌려줍니다.
